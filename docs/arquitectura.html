Arquitectura del Marine Engine Monitor

Sistema de monitorizacion de sala de maquinas basado en ESP32. El firmware recoge sensores, publica telemetria por MQTT y el backend Docker la almacena en InfluxDB para visualizarla en Grafana. Tambien existe un cliente M5 Dial que se suscribe al mismo topic para mostrar datos en pantalla.

ESP32 + Arduino MQTT / Mosquitto Telegraf InfluxDB 2.7 Grafana M5 Dial

Vista General

Capa de sensores

Mediciones conectadas al ESP32.

  • SHT41: temperatura y humedad de sala.
  • INA219: tension de bateria.
  • MAX31865 + PT100: temperatura de escape.
  • Entrada RPM en GPIO 25 por interrupcion.
I2C / SPI / GPIO
Firmware principal

firmware/src/main.cpp coordina el ciclo.

  • Inicializa sensores, WiFi, escaneo I2C y MQTT.
  • Lee sensores cada 2 segundos.
  • Publica JSON cada 1 segundo si hay MQTT.
MQTT JSON
Backend y visualizacion

Stack local definido con Docker Compose.

  • Mosquitto recibe boat/engine/data.
  • Telegraf consume JSON y escribe en InfluxDB.
  • Grafana consulta InfluxDB para dashboards.

Firmware ESP32

Proyecto PlatformIO en firmware/, entorno esp32dev, framework Arduino y librerias PubSubClient, ArduinoJson, Sensirion SHT4x, Adafruit INA219 y MAX31865.

Modelo de datos

EngineData agrupa rpm, exhaustTemp, batteryVoltage, engineRoomTemp y engineRoomHumidity.

Cliente M5 Dial

Proyecto separado en M5stack dial mqtt test/. Se conecta a WiFi, se suscribe a boat/engine/data, parsea JSON y muestra temperatura y humedad.

Flujo de Datos

Captura fisica

Los sensores entregan lecturas al ESP32 por I2C, SPI y una entrada digital con interrupciones para RPM.

Normalizacion en firmware

handleSensors() actualiza una estructura EngineData. El RPM se calcula con pulsos acumulados por segundo.

Publicacion MQTT

mqtt_manager.cpp serializa los campos como JSON y publica en boat/engine/data mediante Mosquitto en el puerto 1883.

Ingestion historica

Telegraf consume el topic MQTT, interpreta el payload como JSON y escribe la medicion engine en el bucket boat de InfluxDB.

Visualizacion

Grafana queda expuesto en el puerto 3000 y puede usar InfluxDB para paneles de estado e historicos.

Servicios del Backend

Mosquitto

Broker MQTT con listener en 1883 y WebSocket expuesto en 9001. La configuracion actual permite clientes anonimos.

InfluxDB

Base de datos temporal expuesta en 8086. Se inicializa con organizacion marine y bucket boat.

Telegraf

Puente MQTT a InfluxDB. Consume boat/engine/data, usa formato json y escribe con outputs.influxdb_v2.

Grafana

Frontend de dashboards en 3000, con datos persistidos en backend/grafana/data y provisioning montado desde el repositorio.

Mapa de Archivos

Firmware

  • firmware/src/main.cpp: arranque y loop principal.
  • firmware/src/sensors.cpp: inicializacion y lectura de sensores.
  • firmware/src/rpmsensor.cpp: contador de pulsos y calculo de RPM.
  • firmware/src/wifi_manager.cpp: conexion y reconexion WiFi.
  • firmware/src/mqtt_manager.cpp: conexion MQTT y publicacion JSON.
  • firmware/include/sensor_data.h: contrato de datos del motor.

Backend

  • backend/docker-compose.yaml: Mosquitto, InfluxDB, Telegraf y Grafana.
  • backend/mosquitto/config/mosquitto.conf: listener MQTT y persistencia.
  • backend/telegraf/telegraf.conf: entrada MQTT y salida InfluxDB.
  • M5stack dial mqtt test/src/main.cpp: cliente visual MQTT para M5 Dial.

Payload MQTT

El ESP32 publica un JSON con esta forma logica:

{
  "rpm": 1200,
  "exhaust_temp": 78.4,
  "battery_voltage": 12.7,
  "engine_room_temp": 31.2,
  "engine_room_humidity": 62.0
}

Nota: este documento resume la arquitectura y evita mostrar credenciales reales. Conviene mover secretos de WiFi, tokens e IPs a configuracion no versionada antes de usar el sistema fuera de pruebas locales.
